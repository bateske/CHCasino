## Design decisions

- Chosen (owner): the top priority is the largest possible dictionary; animation and features come second but must stay on brand with the casino series. Every flash byte saved elsewhere goes to the built-in word list.
- Chosen (owner): name CHWords, title "WORDS". The trademarked name of the board game it follows must not appear anywhere in the repo (code, docs, notes, commit messages), the same policy as CHBoardwalk's.
- Chosen (owner): hybrid dictionary: a compressed core list in flash (plays with no card) plus the full ENABLE list (2-15 letters) as WORDS.DIC on the SD card. README opens with the card install steps.
- Chosen (owner): modes vs CPU (TOURIST / REGULAR / HIGH ROLLER) and 2-player pass-and-play.
- Chosen (owner, visual pass, because the first board looked flat, like a carpet): sizzle over word count that time (the camera, raised tiles and serif letters cost ~3 KB, about 4,000 words). The camera whips between the whole board (8 px squares) and close-up (16 px): close-up while playing; whole board while the CPU thinks, while B is held and at game over.
- Chosen (visual pass): raised ivory tiles with WOOD thickness; premium squares as dark inlays (DL/TL blue, DW/TW red), labelled close up, "2"/"3" from far off; plain squares just dimples ("less is more"); the last play in GOLD. Inspired by CHMahjong's tiles and CHCrossword's zoom.
- Chosen (owner asked): tentative tiles in the chess set's dark-piece tones (SILVER face, BLUE bevel and letter shadow, NAVY edge), lifted off the board; tile letters in CHCrossword's anti-aliased serif (DejaVu Serif Bold, one half-ink tone), 1 px left of centre with a drop shadow; M and W from DejaVu Serif Condensed Bold so every glyph is <= 11 px. Options rows use the serif too; a random word off the card dances as a rainbow banner.
- Rejected: a DAWG (measured 2.7 B/word against ~0.75 for the flash list; `tools/dict/measure.py`). Consequence: the CPU reads the whole flash list (twice) each turn in slices (src/ai/Ai.cpp) instead of walking a graph.
- Chosen without the owner's review (may be changed): unlimited hints (SELECT lays out the best built-in-list play); no penalty for an invalid word; obvious slurs left out of the flash list only (tools/dict/blocked.txt; the card keeps ENABLE as published); two players with no card get "ALLOW IT ANYWAY?"; the glove appears only over the rack.

## Gotchas

- The loop after any code change: `python tools/device.py build`, read check_size's image size, give the headroom to the dictionary (`build_dict.py --bytes N`), rebuild. Nothing fails when the image passes 50,432 B: watch "save pages free: N".
- The built-in list: front coding, Huffman tables chosen by the previous letter, and 24 suffix rules that fold inflections into base words ("closure", roughly doubling words per byte). Encoder `tools/dict/build_dict.py`, decoder `src/dict/FlashDict.cpp`; `src/dict/DictData.*` are generated, never hand-edit.
- `tools/dict/wordlist.py` downloads ENABLE and Norvig's word frequencies into tools/dict/data/ (gitignored) on first use: network needed once. Until then `tools/tests/run_tests.py` still passes but prints "0 ENABLE words checked" (it skips the full-list check): run wordlist.py once in a fresh clone.
- `tools/dict/build_sd.py` writes sdcard/WORDS.DIC (a hash table of 512 B blocks: one block read per lookup, no index in RAM). tools/check.py builds it if missing.
- CPU thinking: on the board `think()` in src/states/Screens.cpp runs `ai::step(24)` until 12 ms have passed each tick (the frame rate sags while it thinks); 12 ms is a guess awaiting device numbers. The simulator's clock does not run while code computes, so there it does a fixed `ai::step(1500)` a tick: frames are deterministic in the sim, but think pacing on the device will differ.
- SD: `src/sd/*` and `tools/chsim/host/{VCard.h,sd_host.cpp}` are generated copies of CHSd (`../../platform/libraries/CHSd`). Never edit them here: edit CHSd, run its tests (`python platform/libraries/CHSd/tests/run_tests.py`), then `python platform/libraries/CHSd/tools/vendor.py` (`--check` verifies the copies), then this game's tools/check.py (paths from the repo root).
- SPI1 is shared with the LCD: SD calls only after `gfx_wait()` and before the next flush (the driver hands SPI1 back as CHGfx left it).
- Simulator card: `CHWD_CARD=<file>`. A `*.img` is served as raw card blocks; any other file is put on a pretend FAT16 card (VCard), so the FAT code runs. Sim-only hooks: `X 0|1` pulls/inserts the card, `A` plays for the human.
- Other debug hooks (list above `debugHook` in src/states/Screens.cpp): `G mode level seed`, `R letters` (rack), `W row col H|V word`, `H` state, `J T|S|O`.
- Tile letters: `tools/tilefont.py` needs DejaVu Serif Bold and Serif Condensed Bold installed (it searches the usual system font folders) and writes tools/art/tilefont.txt; then `python tools/assets.py`. The glove is CHChess's (tools/art/hand.png); the display font's capitals are CHBackgammon's.
- Simulator: `../../tools/chsim/chsim.py` (shared). Set `CHSIM_CXX` or have zig/clang++/g++ on PATH (see root CLAUDE.md). Size report: `../../tools/check_size.py`.
