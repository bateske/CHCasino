# Hardware results, 2026-10-01: the direct route

The menu bootloader (`release/chgame_sdboot.bin`) was installed on a real
CHGame by HARDWARE.md's direct route and the HW3 checklist was run. A person
pressed the buttons and switched the power; a Claude Code session on the PC
ran the commands. No code was changed during the run.

**Outcome.** The bootloader is installed and works. Two things need fixing:
1. **Holding B at power-on does not reach USB mode** (fail, below).
2. **The install box's border is overwritten on the title row** (cosmetic).

One check could not be run on this card (fragmentation), one was not tried
(a second card), and install times were not measured; they are marked.

**Fragmentation**

**Not run: not possible on this card.** With 64 KB clusters every package
(at most 50,928 B) is a single cluster and cannot be fragmented. It needs a
card with clusters of 32 KB or less, e.g. FAT32 formatted with 4 KB clusters.
The operator chose to leave it; `test/native` covers fragmented files.

## Findings

**1. B held at power-on does not skip the menu (fail).**
- *Seen:* holding B (or any button) across power-on always gives the menu.
  The LED stays off. B itself works: it leaves the "USB UPLOAD" screen.
- *Code:* `boot_main()` in `src/boot.c` runs the menu when
  `soft || !b_held()`, and `hal_soft_reset()` in `src/hal.h` reports
  `RCC_SFTRSTF`.
- *Likely cause, not confirmed:* the CH32X035's factory boot code runs first
  at every power-on (it is what samples BOOT/D+) and enters user flash with a
  software reset, so `RCC_SFTRSTF` is always set and B is never read. The USB
  protocol cannot read the reset flags, so this was not checked on the board.
- *Why the PC tests pass:* `test/native/host_hal.c` returns a `soft_reset`
  the test sets itself.
- *Effect:* the escape for a card that upsets the menu is missing. USB with
  the menu on screen and the factory ISP both work, and a card can be pulled.

**2. The install box's border is 1 px on the title row (cosmetic).**
- *Seen:* the pop-up has a 2 px border except beside the game title.
- *Cause (from the code):* titles are padded to 19 characters, so `text_c()`
  in `src/menu.c` draws 114 px from x = 7, over the inner border column on
  each side; `box()` leaves a 112 px interior (x 8..119). Any box with a
  title on its second line is affected.

**3. Notes, not faults.**
- `UP touch` sent while the menu is already up changes nothing on screen;
  "USB UPLOAD / B: MENU" appears when the touch comes from a running sketch.
  The HW3 line should say "from a running game".
- An uploaded build that matches a package on the card shows under its own
  title, not as INSTALLED PROGRAM.
- A running release game does not answer HELLO (`UP probe`: "present, but did
  not answer"; `UP info`: write timeout). That is the expected reading for
  "a game is running", and the same as a crashed sketch.
- The USB serial number differs by mode: `CGFFFFFFFF42B5BE60D888ABCD` with
  CHChess running on COM8, `CGMD888ABCD42B5BE60FFFFFFFF` under
  CHSDtoUSB on COM24 (recovery.md records `JJFFFF...` for an earlier build).
- The fragmentation line needs a note about cluster size (above).
